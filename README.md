# Мульчиці і друзья: атлас

Quarto-сайт з картою 1930-х років (WIG 1:100 000) поверх сучасного знімка, реєстром написів і населених пунктів та методикою. Джерело даних: Google-таблиця. Докладні статті лежать в Obsidian і на сайт не потрапляють.

## Структура

```
_quarto.yml           налаштування сайту
index.qmd             головна
karta.qmd             карта: повзунок прозорості та шторка
toponimy.qmd          реєстр (DT-таблиці)
metodyka.qmd          методика й обмеження
R/helpers.R           налаштування карти (CFG), статуси, функції
data/*.csv            знімок таблиці
scripts/build_tiles.sh  GeoTIFF -> XYZ-тайли
scripts/sync_sheet.R    Google-таблиця -> data/*.csv
tiles/                тайли (створюються скриптом)
docs/                 зібраний сайт (створюється Quarto)
```

## Одноразове налаштування

Потрібні R, Quarto і GDAL (`gdalwarp`, `gdalinfo`, `gdal2tiles`).

```r
install.packages(c("dplyr", "readr", "tibble", "leaflet", "htmltools",
                   "htmlwidgets", "DT", "knitr", "googlesheets4",
                   "leaflet.extras2"))
```

`leaflet.extras2` потрібен лише для вкладки «Шторка». Без нього ця вкладка порожня, решта працює.

## Робочий цикл

1. **Тайли** (коли змінилася геоприв'язка або растр):

   ```bash
   scripts/build_tiles.sh data/raw/wig_merged.tif 11 15
   ```

   Перед цим у QGIS експортуйте растр як GeoTIFF зі 100% непрозорістю. Прозорість задає Leaflet. Скрипт виведе охоплення: за ним виставте `CFG$center` у `R/helpers.R`. Значення `max_native` у `R/helpers.R` має збігатися з останнім зумом.

2. **Дані** (коли додали записи або координати в таблицю):

   ```bash
   Rscript scripts/sync_sheet.R
   ```

   Таблиця має бути відкрита за посиланням. Для приватної таблиці: `GS4_AUTH=1 Rscript scripts/sync_sheet.R`. Без R можна вручну експортувати вкладки «Написи на карті» і «Населені пункти» у CSV та покласти їх як `data/inscriptions.csv` і `data/settlements.csv`. Порядок колонок змінювати не можна.

3. **Перегляд і збірка:**

   ```bash
   quarto preview
   quarto render
   ```

## Публікація

GitHub Pages з папки `docs/`: Settings > Pages > Deploy from a branch > `main` > `/docs`. Якщо Pages ігнорує файли, додайте порожній `docs/.nojekyll`.

Якщо після збірки в `docs/tiles/` порожньо, скопіюйте вручну: `cp -r tiles docs/`.

Якщо тайли важчі за кілька сотень МБ, винесіть їх на окремий хостинг (Cloudflare R2, Netlify) і задайте адресу змінною середовища під час збірки:

```bash
TILES_URL="https://example.com/tiles/wig1931/{z}/{x}/{y}.png" quarto render
```

## Типові проблеми

| Симптом | Що робити |
|---|---|
| Тайли є в preview, але немає на сайті | Перевірити `docs/tiles/`, скопіювати вручну |
| Карта перевернута по вертикалі | Тайли зроблено без `--xyz`: перегенерувати скриптом |
| Стара карта надто бліда | У QGIS растр мав бути 100% непрозорим |
| Чорні або білі поля навколо карти | Передати четвертий аргумент `nodata` у `build_tiles.sh` |
| Міток немає | Заповнити «Широта» і «Довгота» в таблиці, виконати sync |
| Сайт не оновлює дані | Не вмикайте `freeze` у `_quarto.yml`: дані з CSV не відстежуються |

## Що не публікувати

Колонка `obsidian_note` потрібна лише вам. Сторінки сайту її не показують. Не додавайте її до `datatable` і спливних підказок.
